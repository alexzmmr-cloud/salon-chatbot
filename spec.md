# Spec — Чат-бот с ИИ-консультантом (салон красоты)

## Легенда
- Тема: консультационный сервис салона красоты
- Для кого: клиент салона (текущий или потенциальный), который заходит в чат с телефона или ноутбука
- Задача пользователя: быстро узнать про услуги и условия, получить ответ на вопрос и либо оставить заявку самостоятельно, либо через диалог с ИИ-консультантом

## Состав MVP
- Web-чат с историей сообщений, главным меню и полем текстового ввода
- Обычный сценарный bot-flow (без обращения к модели): Услуги, FAQ, Оставить заявку, Обратная связь
- ИИ-консультант поверх той же базы знаний: отвечает на вопросы, помогает выбрать услугу, готовит черновик заявки
- SQLite: заявки (`leads`) и обратная связь (`feedback`) — раздельно, с различимым источником заявки

## Услуги (3-5, для knowledge/services.md)
1. Стрижка и укладка
2. Окрашивание (тон, мелирование, коррекция цвета)
3. Маникюр и педикюр
4. Уход за лицом (чистка, базовые косметологические процедуры)
5. Брови и ресницы (коррекция, окрашивание, ламинирование)

Формат описания каждой услуги: название, короткое описание, цена «от ...», ориентир по времени.

## FAQ-категории (минимум 4, для knowledge/faq.md)
1. **Услуги** — что входит, чем отличаются процедуры
2. **Стоимость** — из чего складывается цена, есть ли доплаты
3. **Сроки / формат работы** — запись, длительность приёма, график салона
4. **Правила / контакты** — отмена и перенос записи, как связаться, адрес

## Данные, которые можно собирать для заявки
- Имя (как обращаться)
- Контакт для связи (телефон или мессенджер — обязательное поле, без него заявку не отправить)
- Услуга, которая интересует
- Краткое описание задачи/пожелания клиента
- Удобное время или день (если пользователь сам называет — необязательное поле)

## Данные, которые бот не должен запрашивать
- Паспортные данные, точный адрес проживания, дату рождения
- Платёжные данные (номера карт, реквизиты)
- Любые данные не по теме заявки на услугу салона
- Никакие данные не запрашиваются «про запас» — только то, что нужно для оформления заявки

## Bot-flow vs ИИ-консультант
- **Bot-flow** — предсказуемые сценарии без обращения к модели: показ каталога услуг, показ FAQ по категориям, форма обычной заявки по фиксированным шагам, форма обратной связи. Работает даже без ключа AI Studio или при исчерпании лимита.
- **ИИ-консультант** — отдельный сценарий поверх LLM (AI Studio API): свободный вопрос пользователя → поиск по knowledge/ → ответ + при необходимости 1-2 уточняющих вопроса → черновик заявки → подтверждение пользователем → сохранение в тот же `leads`, но с другим `source`.
- Оба сценария пишут в одну и ту же БД, но идут разными путями и различимы по `source`.

## Ограничения ИИ-консультанта
- Отвечает только по материалам из `knowledge/` — не выдумывает цены, сроки, скидки, гарантии, которых там нет
- Если информации нет — честно говорит об этом и предлагает оставить заявку, а не даёт произвольный ответ
- Не ведёт свободный разговор на посторонние темы — задача только: услуги компании, FAQ, помощь с заявкой
- Не читает `.env`, файлы вне `knowledge/`, не выполняет shell-команды, не имеет доступа к произвольной файловой системе
- Не сохраняет заявку самостоятельно — только готовит черновик; запись в БД происходит исключительно после явного подтверждения пользователем (Отправить / Изменить / Отмена)
- Не собирает данные сверх списка «Данные, которые можно собирать для заявки»

## План реализации по слоям

### Interface (HTML/CSS/JS)
- Одна страница чата: история сообщений, главное меню (кнопки/пункты), поле текстового ввода
- Переключение между режимами: Услуги, FAQ, Оставить заявку, ИИ-консультант, Обратная связь
- Отображение черновика заявки от ИИ-консультанта с действиями Отправить / Изменить / Отмена

### Backend (Python, FastAPI или Flask)
- Один web-сервер, раздаёт статику интерфейса + API эндпоинты для чата
- Роутинг сообщений: bot-flow (детерминированная логика) vs вызов agent_runtime (ИИ-консультант)
- Чтение конфигурации из `.env` (ключ AI Studio и т.д.), graceful-работа bot-flow без ключа

### Database (SQLite, data/bot.sqlite3)
- Таблица `leads`: session_id, source, service, contact, problem_text, agent_summary, missing_info, status, created_at
  - `agent_summary` — краткая выжимка запроса, которую готовит ИИ-консультант для черновика заявки (для обычного bot-flow может оставаться пустым)
  - `missing_info` — что консультант не смог уточнить у пользователя на момент черновика (для обычного bot-flow пустое)
- Таблица `feedback`: session_id, message_text, created_at
- Обычная заявка → `source = bot_flow`; заявка от консультанта → `source = ai_consultant`

### Agent (ИИ-консультант)
- `agent_runtime.py` — управляет циклом консультации (получить вопрос → вызвать tools → сформировать ответ/черновик)
- `agent/tools.py` — `search_knowledge`, `read_knowledge_file`, `prepare_lead_draft`, `save_confirmed_lead`, с защитой от выхода за `knowledge/` и от чтения `.env`
- `agent/soul.md` — роль, тон, ограничения консультанта
- `knowledge/services.md`, `knowledge/faq.md`, `knowledge/rules.md` — база знаний
- `ai_client.py` — клиент AI Studio API (OpenAI-совместимый), ключ только из `.env`

## Обязательные артефакты
- `.env.example` (без реального `.env` в репозитории)
- `README.md` с инструкциями запуска, кратким MVP-описанием (или отдельный `spec.md`, как этот файл)
- `evidence/screenshots/` — скриншоты локальной проверки и запуска на VPS
- `requirements.txt`

## Явно не входит в scope
- Домен, публичная ссылка на интерфейс
- Отдельный кабинет управления заявками
- Внешний production-контур, HTTPS/reverse-proxy настройка сверх необходимого для запуска runtime
- Многоязычность, авторизация пользователей, оплата онлайн
