# Plan.md: Фаза 4 — confirmation flow и сохранение заявок

## 1. Текущий статус

- Приоритет: `P0`
- Текущее состояние: `завершено`
- Основная цель цикла: довести ИИ-консультанта до продуктового сценария — черновик заявки показывается пользователю с действиями Отправить/Изменить/Отмена, запись в `leads` происходит только после явного подтверждения.
- Обязательное ограничение: `save_confirmed_lead` (tool) уже существует с Фазы 3 и пишет в БД напрямую по вызову модели — в этом цикле его вызов должен происходить только после клика пользователя «Отправить заявку», не раньше и не по решению модели в одностороннем порядке.
- Основной контекст проекта: `spec.md` (Фаза 1), результаты Фазы 3 (`agent_runtime.py`, `agent/tools.py`).
- Секреты: без изменений — `YC_API_KEY`/`YC_FOLDER_ID` только из `.env`.
- Сейчас в работе: `1. Черновик как отдельная стадия без записи в БД`.

## 1.1 Целевой сценарий

Пользователь в режиме ИИ-консультанта:

1. Общается с консультантом, тот собирает данные для заявки (услуга, контакт, описание).
2. Консультант вызывает `prepare_lead_draft` (без записи в БД) и показывает пользователю структурированный черновик: услуга, краткое описание задачи, контакт, что уже известно, чего не хватает.
3. Под черновиком появляются 3 действия: «Отправить заявку», «Изменить», «Отмена».
4. Пользователь нажимает «Отправить заявку» → бэкенд вызывает `save_confirmed_lead` → строка появляется в `leads` с `source = ai_consultant` → пользователь получает подтверждение.
5. Альтернатива: пользователь нажимает «Изменить» → консультант спрашивает, что поправить, диалог продолжается, новый черновик формируется заново.
6. Альтернатива: пользователь нажимает «Отмена» → черновик отбрасывается, ничего не пишется в `leads`, диалог с консультантом продолжается в обычном режиме.

## 1.2 Что не входит в текущую версию

- Изменение схемы `leads`/`feedback` (используется как есть с Фазы 2)
- Редактирование уже сохранённой (подтверждённой) заявки
- Деплой на VPS (Фаза 6)

## 1.3 Допущения и открытые вопросы

### Допущения

- Черновик заявки отображается в интерфейсе как обычное сообщение бота с 3 кнопками действия под ним — переиспользуется существующий механизм `menu` в ответе `/api/chat` (Фаза 2), а не отдельный HTML-компонент.
- Черновик хранится на бэкенде в состоянии сессии (`_drafts` в `agent_runtime`), а не передаётся клиентом обратно — так исключается подмена данных заявки на стороне браузера.
- Нажатие кнопки «Отправить заявку» / «Изменить» / «Отмена» реализовано как обычное текстовое сообщение с этим текстом (как остальные пункты меню в Фазе 2), сравнение — по нормализованному тексту (`.strip().lower()`, та же нормализация, что уже используется в `bot_flow.py`), специальный протокол кнопок не вводится.
- «Изменить» не сбрасывает диалог — агент получает системную подсказку спросить пользователя, что именно поправить, и черновик формируется заново после уточнения.
- **`agent_summary` для `save_confirmed_lead`**: `prepare_lead_draft` дополняется полем `agent_summary` (короткая выжимка запроса, формулирует сама модель при вызове tool — обязательный параметр). Черновик, показываемый пользователю, и данные, передаваемые в `save_confirmed_lead` при подтверждении, используют один и тот же объект из `_drafts[session_id]` — значение `agent_summary` не запрашивается повторно.
- **Текст, не совпадающий ни с одной из 3 команд, при активном черновике**: уходит в модель как обычное сообщение диалога (черновик в `_drafts[session_id]` не сбрасывается и не теряется); в системный контекст запроса к модели добавляется техническая пометка о том, что есть неподтверждённый черновik, — модель может либо ответить на вопрос пользователя, либо напомнить про три доступных действия. Черновик сбрасывается только явными командами (шаги 2-4) или новым вызовом `prepare_lead_draft`.

### Вопросы, которые нельзя восстановить из входа

- Нет открытых вопросов, блокирующих этот цикл.

## 2. Требования к результату

- Модель физически не получает tool `save_confirmed_lead` в списке доступных функций вне момента явного подтверждения пользователем — `save_confirmed_lead` вызывается только backend-кодом в ответ на текстовую команду «отправить заявку» при активном черновике, а не по решению модели.
- Действие «Отправить заявку» сохраняет строку в `leads` (`source = ai_consultant`) и очищает черновик из состояния сессии.
- Действие «Изменить» не создаёт запись в БД, возвращает пользователя к уточнению в диалоге с консультантом.
- Действие «Отмена» не создаёт запись в БД, явно сообщает пользователю, что заявка не сохранена, диалог с консультантом продолжается.
- Черновик из `agent_runtime` не путается с обычной заявкой bot_flow — оба пишут в один `leads`, но различаются `source`.
- Схему `leads`/`feedback` не менять.

## 2.1 Раскладка по слоям

### Frontend
- Не затрагивается технически (кнопки под сообщением уже рендерятся общим механизмом `menu` из Фазы 2) — только проверка, что 3 новые кнопки-действия корректно отображаются и кликабельны, как обычные пункты меню.

### Backend
- `agent_runtime.py` — новое состояние `_drafts: dict[str, dict]` на сессию; отдельная обработка входящего текста, когда есть незавершённый черновик («Отправить заявку» / «Изменить» / «Отмена» перехватываются до ухода в модель).
- **Программный guard для `save_confirmed_lead`**: `TOOL_SCHEMAS` (описание tool для модели) для `save_confirmed_lead` убирается из списка `tools`, передаваемого в `ai_client.chat_completion(...)`, пока нет активного подтверждённого намерения пользователя — то есть модель физически не может вызвать этот tool в рамках обычного диалога, он не в списке доступных функций. Единственный путь его вызова — прямой вызов `tools.save_confirmed_lead(...)` из backend-кода на шаге 2, в ответ на текстовую команду «отправить заявку» при активном `_drafts[session_id]`. Модель продолжает видеть tool `prepare_lead_draft` всегда.
- Если модель по какой-то причине всё же вернёт `tool_call` с именем `save_confirmed_lead` (например, «галлюцинация» вызова несуществующего в текущем наборе tool) — `agent_runtime.py` не находит его в активном `TOOL_FUNCTIONS`-подмножестве для этого запроса и возвращает tool-результат с ошибкой `{"error": "tool not available in this context"}`, запись в БД не происходит.

### Database
- Не затрагивается — схема `leads`/`feedback` с Фазы 2 без изменений.

### Agent
- `agent/soul.md` — дополнить инструкцией: предлагать черновик через `prepare_lead_draft`, никогда не звать `save_confirmed_lead` без явного подтверждения пользователя (хотя это дублируется программной проверкой backend, отражается и в промпте для консистентности поведения модели).

## 5. Критерии готовности проекта

- Черновик заявки создаётся отдельно от сохранения лида (`prepare_lead_draft` не пишет в БД).
- Действие «Отправить заявку» сохраняет строку в `leads`.
- Действие «Изменить» возвращает пользователя к уточнению, не пишет в БД.
- Действие «Отмена» не создаёт строку в `leads`.
- Заявка из ИИ-консультанта имеет `source = ai_consultant`.
- Обычная заявка (bot_flow, Фаза 2) продолжает иметь `source = bot_flow`.
- В SQLite различимы: обычная заявка, заявка из ИИ-консультанта, обратная связь.
- Сохранение заявки не требует отдельного кабинета управления или ручной обработки.
- `Plan.md` содержит отметки выполненных шагов и заполненные «Итог» по каждому.
