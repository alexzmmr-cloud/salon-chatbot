Формальному требованию («видно, что данные сохранились», различимые source) это не противоречит — не блокер, зафиксировано как заметка.

- [x] 5. Скриншот VPS runtime (05)

  - Действие: пользователь вручную снял скриншот терминала с выводом `sudo systemctl status salon-bot --no-pager` и `sudo systemctl status nginx --no-pager`.

  - Проверка: оба сервиса `active (running)`, ошибок в логах нет.
  - Итог: ревьюер подтвердил PASS.

- [x] 6. Найденный и исправленный баг: `crypto.randomUUID()` вне secure context
  - Вход: попытка снять скриншот 01 показала пустой экран — ни приветствия, ни меню.
  - Диагностика: `crypto.randomUUID()` в `interface/app.js` (генерация `session_id`) недоступен в браузере вне secure context (HTTPS или `localhost`) — на VPS сайт открыт по голому HTTP на публичном IP, поэтому вызов падал с `crypto.randomUUID is not a function` ещё до рендера меню, весь `app.js` не выполнялся дальше этой строки.
  - Действие: заменено на собственный генератор id без `crypto` (`Date.now().toString(36) + Math.random().toString(36).slice(2)`), задеплоено на сервер поверх статики (без рестарта сервиса — файл отдаётся `StaticFiles` с диска).
  - Результат: интерфейс работает по HTTP на голом IP без деградации.
  - Проверка: headless-браузер дождался `#menu button` и отрисовал меню; повторное ревью скриншота 01 — PASS.
  - Итог: баг был не в architecture-scope Фазы 5 (обнаружен случайно при подготовке скриншотов), но критичный для продакшена — без фикса бот вообще не работал в браузере на реальном VPS-домене/IP без HTTPS. Исправлен и задеплоен в рамках этого же цикла.
